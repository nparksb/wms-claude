## Why the script halted on web-ui — and why we kept the manual approach

The first cherry-pick (`20ab082`) conflicted on 16+ files in `store/admin/`, `store/processes/`, `store/reports/`. Inspection of one (`store/reports/data.js`) showed the cause:

- v1 commit changes `// this.$toast.error('Error: ' + error)` → `this.$toast.error('Error: ' + error)` (uncomment + emit raw error).
- v2 already has `this.$toast.error('Error: Request failed due to a network or server issue. Please retry.')` (polished message).

Same for `29e62e0`. Both v1 commits are content-superseded by v2 commits `26069e9` + `2639596`. Cherry-picking them would clobber v2's better messages.

Decision: abort the script's full-range cherry-pick, fall back to **single-commit cherry-picks** of the only genuinely-new content in the range (`1d80e43` and `43dd052`), and document the rest in this report.
