**LANDMINE (reusable):** a service-layer sysprop branch CANNOT guard a Spring Data REST `@RestResource`-exported repository query — HTTP invokes the ORIGINAL method, bypassing any `_excludingLanes` twin. `StockunitRepository` source queries `:164/:181/:197` are HAL-exported (no `exported=false`); the frontend open-request replenishment screen (`wms2-web-ui .../openRequest.vue`, `store/internalOps/replenishments.js`) calls `getStockUnitsForReplenishment`/`getStockUnitInfoForReplenishment` directly. Fix pattern: gate by EXPOSURE — add `exported=false` + boolean-param query for service-branchable ones (`:213` and `UnitloadRepository:135` already exported=false); guard HAL-exposed ones UNCONDITIONALLY in the query body (safe because `calculateOrder` re-selects its own source, takes no caller-chosen sourceStockId — display-only leak). Use `AND (:excludeLanes = FALSE OR (loc.staginglane IS NOT TRUE AND loc.transferlane IS NOT TRUE))` — constant-folds plan-identical when OFF (the "native @Query can't toggle inline" claim is FALSE for a bound boolean; `OR :param=''` hazard is string-only).

**⚠ SHARPENED 2026-08-12 by a second occurrence (SBDEV-2643 A4, review finding M1).** The landmine above says "`@RestResource`-exported", which reads as *"look for the annotation"*. **The real rule is the opposite: on a repo carrying `@RepositoryRestResource`, query methods are exported BY DEFAULT — the ABSENCE of an annotation means exported.** `RestConfiguration.java:47` sets `RepositoryDetectionStrategies.ANNOTATED`, which selects which *repositories* are exposed, **not** which methods. So a new `@Query` method with no annotation silently becomes `GET /v3/<path>/search/<methodName>`, reachable by any `wms_user` (`SecurityConfiguration` maps `/v3/**` to that authority). In A4 this published a name-search query whose service-side guard normalises blank terms — the HTTP path bypassed the guard and would run `LIKE '%%'`, falsifying an invariant the method's own javadoc asserted. Fix: `@RestResource(exported = false)` on any new repository query that a service-layer guard is relied on to constrain. **Check the whole file's convention, not one neighbour** — in `LocationRepository` 19 of 21 methods are explicit, and the one I copied was the file's only anomaly.
