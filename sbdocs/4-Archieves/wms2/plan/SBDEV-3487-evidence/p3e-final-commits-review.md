### Commit e69070e9 — message text rewrite

**(a) Every thrower is CLOSED-only.** `git grep` finds exactly two throwers of the key:
- `BillofladingPositionService.assertPalletNotShipped` (`:44-47`) — only throws when `findClosedBolNameBySourceUnitLoadLabel` returns non-null; the query and its javadoc are CLOSED-specific (`WmsConstants.BillOfLadingState.CLOSED`).

No other throw sites exist. The new text ("already shipped on closed BOL") is true in every case. **No issue.**

**(b) Format specifiers.** `%1s`/`%2s` (no `$`) are non-positional Java `Formatter` width specifiers — width `1`/`2`, general (sequential) argument index, not "argument 1"/"argument 2". Both call sites pass `(palletLabel, bolName)` in the same order the two specifiers appear, so this happens to be correct, but it is not "positional" in the way the digits suggest. This is a pre-existing bundle idiom (`scannedAndRequiredGateDiffer` uses the same bare form two lines up; `noValidString` two lines above that uses the real positional `%1$s` — the file already mixes both conventions). The new text adds no extra `%` beyond the original two, so it doesn't newly risk `BusinessException`'s `IllegalFormatException` fallback.
- **[LOW] Confidence: MEDIUM** — File: `src/main/resources/messages_en_US.properties:331`. Not a new bug, but worth a follow-up ticket to normalize `%1s`→`%1$s` across the file so a future edit that reorders args doesn't silently swap the wrong value in.
